Get started with kcoap

kcoap is not released yet. You build a snapshot from source, publish it to your local Maven repository and depend on it from there: three steps, then a guide for your platform.

Before you start

Prerequisites

What you need to build the snapshot, and what your project needs to use it.

To build kcoap
Git and a JDK 17 or newer. Gradle comes with the wrapper; it is set to use up to 3 GB of memory, and the Kotlin daemon up to 2 GB.
JVM bytecode
Java 17. Your project compiles to Java 17 or newer.
Kotlin
2.3 or newer in your project; kcoap is built with Kotlin 2.4.21. For native and web targets, use 2.4.21 or newer.
Android
API level 26 (Android 8.0) or later.
iOS and macOS
A Mac with Apple silicon and Xcode. No minimum OS version is set yet.
Browsers and Node.js
No minimum version is set. Kotlin/Wasm needs a browser with WebAssembly garbage collection.

Install

Three steps, on every platform

These steps are the same for every target. The platform guides repeat them with the build file that target needs.

  1. Clone the work branch and publish to Maven Local

    The code lives on the branch feat/protocol-core until pull request #1 merges; main still holds only the first skeleton. The build needs a JDK 17 or newer and downloads the rest. For iOS and macOS apps, run it on a Mac with Xcode.

    Terminal

    git clone --branch feat/protocol-core https://github.com/adihack/kcoap.git
cd kcoap
./gradlew publishToMavenLocal  # dev.kcoap:*:0.1.0-SNAPSHOT into ~/.m2/repository

  2. Add Maven Local and the modules you need

    Let Maven Local serve only the dev.kcoap group, so nothing else in it leaks into your build. Use one version for every kcoap module: the modules share internal plumbing, and mixed versions are not supported.

    Kotlin DSL

    build.gradle.kts

    repositories {
    // kcoap from publishToMavenLocal, and nothing else from Maven Local
    mavenLocal { content { includeGroup("dev.kcoap") } }
    mavenCentral()
}

dependencies {
    val kcoap = "0.1.0-SNAPSHOT"
    implementation("dev.kcoap:kcoap-coap:$kcoap")            // client, server
    implementation("dev.kcoap:kcoap-transport-ktor:$kcoap")  // UDP, TCP
    implementation("dev.kcoap:kcoap-crypto-default:$kcoap")  // cryptography
    implementation("dev.kcoap:kcoap-oscore:$kcoap")          // OSCORE
    implementation("dev.kcoap:kcoap-edhoc-oscore:$kcoap")    // EDHOC, OSCORE
}

    Version catalog

    gradle/libs.versions.toml

    [versions]
kcoap = "0.1.0-SNAPSHOT"

[libraries]
kcoap-coap = { module = "dev.kcoap:kcoap-coap", version.ref = "kcoap" }
kcoap-transport-ktor = { module = "dev.kcoap:kcoap-transport-ktor", version.ref = "kcoap" }
kcoap-crypto-default = { module = "dev.kcoap:kcoap-crypto-default", version.ref = "kcoap" }
kcoap-oscore = { module = "dev.kcoap:kcoap-oscore", version.ref = "kcoap" }
kcoap-edhoc-oscore = { module = "dev.kcoap:kcoap-edhoc-oscore", version.ref = "kcoap" }

[bundles]
kcoap = ["kcoap-coap", "kcoap-transport-ktor", "kcoap-crypto-default", "kcoap-oscore", "kcoap-edhoc-oscore"]

    build.gradle.kts

    repositories {
    mavenLocal { content { includeGroup("dev.kcoap") } }
    mavenCentral()
}

dependencies {
    implementation(libs.bundles.kcoap)
}

    In a Kotlin Multiplatform project the same coordinates go into commonMain.dependencies, except the adapters a target lacks: browsers and Node.js use kcoap-transport-ktor-websocket instead of kcoap-transport-ktor.

  3. Follow the guide for your platform

    Each guide has the build file for its target, a first client and server, and the notes that matter there: transports, the crypto backend, minimum versions and what is not done yet.

After the first release

The coordinates will be dev.kcoap:<module>:<version> from mavenCentral(), once the dev.kcoap namespace is verified. Each release also goes to GitHub Packages. Neither has a kcoap artifact yet; Releases says what has to happen first.

Modules

Which modules to add

Sixteen modules are published. An application usually needs four or five of them; the rest come in as dependencies.

ModuleAdd it forTargets
kcoap-coapCoapClient and CoapServer; brings the message model, the transport interfaces and kotlinx.coroutinesall
kcoap-crypto-defaultThe platform’s cryptography. No other module brings it: every app adds it, or kcoap-crypto-bcall
kcoap-transport-ktorUDP (coap) and TCP (coap+tcp) sockets on ktor-networkJVM, Android, Apple, Linux
kcoap-transport-ktor-websocketThe WebSocket client (coap+ws, coaps+ws)all
kcoap-transport-ktor-websocket-serverThe WebSocket server, with a ktor server engine you add, such as io.ktor:ktor-server-cioJVM, Apple, Linux
kcoap-oscoreOSCORE with pre-shared keys; add kcoap-coap too to run it through the client and serverall
kcoap-edhoc-oscoreEDHOC over CoAP, into OSCORE, with the combined request; brings kcoap-edhoc, kcoap-oscore and kcoap-coapall
kcoap-crypto-bcPost-quantum EDHOC: ML-KEM and ML-DSA on Bouncy Castle; brings kcoap-crypto-defaultJVM, Android
kcoap-testkitTests without a network: a lossy in-memory network and in-memory connections on virtual timeall

The other published modules (kcoap-common, kcoap-crypto, kcoap-cbor, kcoap-cose, kcoap-transport, kcoap-coap-message, kcoap-edhoc) come in through these. kcoap-dtls is built and tested but not published until its engine exists. All modules in the README.

Help

If the build cannot find kcoap

Could not find dev.kcoap:…:0.1.0-SNAPSHOT
Run ./gradlew publishToMavenLocal in the clone, then check that mavenLocal() is in your repositories and its content filter names dev.kcoap. In a settings file with dependencyResolutionManagement, the repositories go there.
The clone has no kcoap-coap-message or transport modules
It is on main, which holds only the first skeleton. Clone with --branch feat/protocol-core.
Some kcoap classes are missing at runtime
Check that every kcoap module has the same version.
Still stuck
SUPPORT.md says where to ask. Each platform guide has its own troubleshooting list.
