# Third-party material

kcoap's own code is licensed under the [Apache License 2.0](../LICENSE); see also [NOTICE](../NOTICE).
This page lists what in this repository and in kcoap's published artifacts comes from others: where it
lives, where it comes from, its license, and whether it ships.

Each license below comes from the item's own declaration: the POM of a Maven artifact, a license file
inside a jar or klib, or the upstream repository's license file. **Unconfirmed** marks what was not
checked at the exact version kcoap uses.

## At a glance

| Material | Where it lives | Ships in kcoap's artifacts? |
|---|---|---|
| [Runtime libraries](#runtime-dependencies): Kotlin, kotlinx, cryptography-kotlin, ktor, Bouncy Castle | declared in each module's `build.gradle.kts`, versions in `gradle/libs.versions.toml` | No. They are declared as dependencies in the POM and Gradle module metadata; the consumer's build downloads them |
| [Test vectors](#test-vectors) from IETF RFCs, NIST, the GCM specification and the COSE Working Group's examples | test source sets (`src/*Test`), generated by `tools/`; the conformance suite's in `kcoap-crypto-testsuite/src/commonMain` | Only in `kcoap-crypto-testsuite`, the conformance suite for tests: NIST's ACVP ML-KEM and ML-DSA vectors and one known answer per algorithm |
| [Interop peers](#interop-material): libcoap, libedhoc and their dependencies | built inside Docker images from `interop/` | No. The images are built locally and in CI, and never published |
| [Gradle wrapper](#build-and-test-tooling) | `gradlew`, `gradlew.bat`, `gradle/wrapper/` | No |
| [Build plugins and test tools](#build-and-test-tooling) | downloaded by Gradle and Yarn when building | No |

A published kcoap module contains kcoap's compiled code (a jar or a klib per target), a sources jar of
its main source sets, an empty javadoc jar, a POM and Gradle module metadata. The JVM jar of
`kcoap-crypto-default` also carries a ProGuard/R8 rules file that kcoap wrote. No third-party code is
copied into any of them, and third-party data only into `kcoap-crypto-testsuite`: the
[test vectors](#test-vectors) its conformance suites replay.

### Platform cryptography

`kcoap-crypto-default` uses cryptography-kotlin's "optimal" provider, which calls the platform's own
cryptography: the JDK's providers on the JVM and Android, CryptoKit and CommonCrypto on Apple targets,
and WebCrypto in browsers and Node.js. Those are part of the platform and are not redistributed.

On `linuxX64` the provider is `cryptography-provider-openssl3-prebuilt`, whose klib contains OpenSSL
3.6.0 as a static library (`libcrypto.a`, Apache-2.0). It does not ship in kcoap's artifacts, but it is
linked into every Linux executable that uses `kcoap-crypto-default`, so whoever distributes such an
executable also distributes OpenSSL.

## Test vectors

Tests check kcoap against the examples that standards publish. The vectors live in test source sets,
which are not published, except those of the conformance suite: `kcoap-crypto-testsuite` is a published
test library, so its vectors and known answers ship in its artifacts. The `tools/` scripts download the source documents and extract the
values, so they are not typed in by hand ([testing](testing.md)).

| Source | Values | Where |
|---|---|---|
| RFC 3610 §8 (AES-CCM), RFC 5869 Appendix A (HKDF), RFC 8613 Appendix C (OSCORE key derivation) | generated by `tools/regen-vectors.sh` and `tools/gen_vectors.py` | `kcoap-crypto-default/src/commonTest/.../vectors/` |
| RFC 9529 (EDHOC traces) | generated by `tools/regen-vectors.sh` and `tools/gen_edhoc_vectors.py` | `kcoap-edhoc/src/commonTest/.../vectors/Rfc9529Vectors.kt` |
| RFC 7748 §6.1, RFC 8032 §7.1, RFC 4231 test case 1, RFC 8949 Appendix A, RFC 8613 Appendix C, RFC 8323 figures, RFC 9529 §4, RFC 9668 Figure 4 | single examples written into tests | tests of `kcoap-crypto-default`, `kcoap-crypto-bc`, `kcoap-cbor`, `kcoap-cose`, `kcoap-coap-message`, `kcoap-coap`, `kcoap-oscore`, `kcoap-edhoc`, `kcoap-edhoc-oscore` |
| NIST ACVP-Server, commit `975de31eb83d` (ML-KEM, FIPS 203; ML-DSA, FIPS 204) | generated by `tools/regen-pq-vectors.sh` and `tools/gen_pq_vectors.py` | `kcoap-crypto-testsuite/src/commonMain/.../vectors/` (published) |
| RFC 3610 §8 packet 1, the GCM specification's test cases 2, 8 and 14 (McGrew and Viega), RFC 8439 §2.8.2, RFC 7748 §6.1 and §6.2, RFC 5903 §8.1 and §8.2, RFC 8032 §7.1 TEST 1, RFC 6979 §A.2.5 and §A.2.6, FIPS 180-4 and FIPS 202 examples, RFC 4231 test case 1 | single known answers written into the suite, each with its source | `kcoap-crypto-testsuite/src/commonMain/.../KnownAnswers.kt` (published) |
| COSE Working Group examples ([cose-wg/Examples](https://github.com/cose-wg/Examples), commit `53c9d634`): `aes-ccm-examples/aes-ccm-enc-02` to `-08` | key, nonce, `Enc_structure` and ciphertext of each, written into the suite with its source | `kcoap-crypto-testsuite/src/commonMain/.../KnownAnswers.kt` (published) |
| FIPS 180-4, FIPS 197 Appendix C, FIPS 202, NIST SP 800-185 | single known answers written into tests | tests of `kcoap-crypto`, `kcoap-crypto-default`, `kcoap-crypto-bc` |
| SEC 2 §2.4.2 and §2.5.1 (curve base points) | domain parameters written into tests, with multiples of them computed independently | `kcoap-crypto/src/commonTest/.../EcPoints.kt`, `kcoap-dtls/src/commonTest/.../TestCredentials.kt`, `kcoap-cose` tests |
| RFC 9529 §2 and §3 (certificates and P-256 keys of the EDHOC traces) | copied from the generated trace vectors | `kcoap-crypto/src/commonTest/.../x509/Rfc9529Certificates.kt`, `EcPoints.kt`, `kcoap-cose` tests |

**Terms.**

- **IETF RFCs** are copyright the IETF Trust and the persons identified as the document authors (RFCs
  before 2009, such as RFC 3610 and RFC 4231, the Internet Society). The
  [IETF Trust Legal Provisions](https://trustee.ietf.org/license-info) license "Code Components" of
  RFCs under the Revised BSD License, and their list of code components includes "tables of values" and
  CBOR. Whether these test vectors count as code components is **unconfirmed**; read as such, the
  Revised BSD License asks that the copyright notice and license conditions stay with them. The
  generated files do not carry them yet: their headers name only the RFC and the generator. A
  follow-up has `tools/gen_vectors.py` and `tools/gen_edhoc_vectors.py` write each RFC's copyright line
  and a pointer to the IETF Trust Legal Provisions into the files they generate. The same follow-up covers
  `kcoap-crypto-testsuite`'s `KnownAnswers.kt`, which ships and names each RFC next to its values.
- **NIST** material: software and data developed by NIST employees is not subject to copyright
  protection in the United States. The ACVP-Server README asks users to acknowledge NIST as the source;
  the generated files and this page do.
- **The GCM specification** (McGrew and Viega, "The Galois/Counter Mode of Operation", submitted to NIST)
  publishes the AES-GCM test cases. No license terms for them were found (**unconfirmed**).
- **The cose-wg Examples** repository is released under the Unlicense, a public-domain dedication (its
  `LICENSE` file at commit `53c9d634`, where the AES-CCM examples are unchanged since 2016); it asks for
  nothing to be kept with the values.
- **SEC 2** base points are curve constants, published by the Standards for Efficient Cryptography Group
  and repeated in other standards. No license terms for them were found (**unconfirmed**).

## Interop material

The interop tests run reference implementations in Docker containers ([interop](../interop/README.md)).
The repository holds only the recipes; Docker downloads and builds the third-party code inside the image.
The images are built on the developer's machine and in CI, and are never pushed to a registry.

| Item | Where | Source | License |
|---|---|---|---|
| libcoap v4.3.5b | built by `interop/libcoap/Dockerfile` | https://github.com/obgm/libcoap, tag `v4.3.5b`, unmodified | BSD-2-Clause, with some files under other permissive licenses that its `LICENSE` lists. Read from the `develop` branch; the tag's file is **unconfirmed** |
| libedhoc `0363bd3` | built by `interop/libedhoc/Dockerfile` | https://github.com/kamil-kielbasa/libedhoc, pinned commit | MIT. Read from the `main` branch; the pinned commit's file is **unconfirmed** |
| libedhoc's vendored dependencies: Mbed TLS, liboqs, XKCP, zcbor, Compact25519 | git submodules of libedhoc, inside the image | their upstream projects | **unconfirmed** at the pinned versions |
| Ubuntu 24.04 and its packages (OpenSSL, compilers, CMake) | base image of both Dockerfiles | Ubuntu archive | their own licenses |
| `edhoc_peer` | `interop/libedhoc/peer/` | kcoap's own code (Apache-2.0); it uses libedhoc's public headers and two internal ones | Apache-2.0 |
| `coap.sh` | `interop/libcoap/coap.sh` | kcoap's own script | Apache-2.0 |

**Modification of libedhoc.** No patch files exist. To build `edhoc_peer` inside libedhoc's build tree,
`interop/libedhoc/Dockerfile` appends one `add_subdirectory(...)` line to libedhoc's top-level
`CMakeLists.txt`, in the image only. libcoap is built as released.
